# QR Code Generator & Decoder

Консольна програма для шифрування BIP-39 сід-фраз паролем і збереження результату у QR-код, а також для розшифрування з QR-коду або з тексту.

> [!WARNING]
> **Сід-фраза дає повний доступ до ваших коштів.** Програма захищає її, як може, але не може контролювати термінал, буфер обміну чи інші програми на вашому комп'ютері. Перед першим використанням прочитайте розділ [Безпека](#безпека): особливо [Перед запуском](#перед-запуском) та [Відомі обмеження](#відомі-обмеження).

## Швидкий старт

Потрібен .NET 11 SDK (`dotnet --version` → 11.x).

```bash
cd QrCodeGenerator
dotnet run -c Release --project QrCodeGenerator.csproj
```

Для реального використання запускайте **Release**-збірку (`-c Release`): Debug-збірка містить тестовий перемикач для e2e-тестів.

Запускайте лише в інтерактивному терміналі. Перенаправлений ввід (`echo 1 | dotnet run ...`) програма відхиляє з кодом виходу 2.

## Безпека

### Перед запуском

| ✅ Робіть | ❌ Не робіть |
|---|---|
| Запускайте в окремому вікні Terminal.app, iTerm2 або іншого звичайного терміналу | Не запускайте у вбудованих терміналах редакторів (VS Code, Cursor, JetBrains) |
| Вимкніть журналювання сесії (iTerm2: Settings → Profiles → Session → Automatically log session input/output) | Не запускайте в терміналах з AI-помічниками (Warp AI, Copilot у терміналі тощо): вони читають вивід |
| Вимкніть відновлення вмісту вікон (Terminal.app: Settings → Profiles → Window → «Restore text when reopening windows»; macOS: System Settings → Desktop & Dock → «Close windows when quitting an application») | **Ніколи не дозволяйте AI-агентам запускати програму чи читати її вивід**: усе, що вони бачать, потрапляє в їхні журнали й може зберігатися назавжди |
| Переконайтеся, що екран ніхто не бачить, і вимкніть демонстрацію та запис екрана | Не запускайте всередині tmux/screen, якщо не потрібно: вони мають власну історію прокрутки |
| Тримайте QR-код і зашифрований текст подалі від хмарних тек (iCloud Desktop/Documents, Dropbox) | Не копіюйте сід-фразу через буфер обміну |

### Що робить програма для захисту

- **Маскований ввід.** Сід-фраза й пароль відображаються як `*` під час введення; Backspace працює. Набрані символи не з'являються на екрані навіть при посимвольному введенні чи введенні наперед (перевірено e2e-тестами).
- **Помилки без секретів.** Повідомлення про невірну сід-фразу чи пароль ніколи не містять введених слів.
- **Показ лише за запитом.** Розшифрована сід-фраза показується тільки після підтвердження `y`. Зашифрований текст після створення QR-коду також не виводиться, доки ви про це не попросите.
- **Автоматичне очищення терміналу.** Див. [Очищення терміналу](#очищення-терміналу).
- **Захист пам'яті.** Сід-фраза, пароль, ключ шифрування й розшифровані дані зберігаються в закріплених (pinned) буферах фіксованого розміру. Вони ніколи не перетворюються на звичайні рядки .NET і обнуляються одразу після використання.
- **Відмова при перенаправленні.** Програма не читає секрети з перенаправленого вводу (`echo ... | програма`) і не показує їх у перенаправлений вивід (`програма > файл`). Це не дає скрипту чи агенту непомітно провести через неї сід-фразу.
- **Лише локальна робота.** Жодних мережевих з'єднань; перевірка слів BIP-39 відбувається локально.

### Очищення терміналу

Програма очищає **і видимий екран, і історію прокрутки** (scrollback):

| Коли | Що відбувається |
|---|---|
| Після показу сід-фрази або зашифрованого тексту | Текст лишається на екрані, доки ви не натиснете будь-яку клавішу; потім екран і прокрутка очищаються |
| Звичайний вихід | Очищення перед прощальним повідомленням |
| Ctrl+C | Очищення перед завершенням (код виходу 130) |
| Неочікувана помилка | Спочатку очищення, потім повідомлення про помилку (код виходу 1) |

Очищення виконується, лише якщо під час сесії вводилися або показувалися секрети. На macOS і Linux програма надсилає `ESC[2J` + `ESC[3J` (очищення прокрутки); на Windows використовується `Console.Clear()`.

Перевірено автоматичними e2e-тестами (див. [Тести](#тести)):

| Термінал | Очищення прокрутки | Перевірено |
|---|---|---|
| tmux | ✅ | e2e-тести |
| macOS Terminal.app | ✅ | e2e-тести |
| iTerm2 | ✅ | e2e-тести |
| Windows Terminal / conhost | ⚠️ може зберігати прокрутку | не перевірено |
| Інші (Alacritty, kitty, WezTerm, GNOME Terminal…) | залежить від підтримки `ESC[3J` | не перевірено |

**Перевірте свій термінал:** розшифруйте один із [тестових прикладів](#тестові-дані), покажіть сід-фразу, натисніть клавішу, а потім прокрутіть угору або знайдіть слово через ⌘F / Ctrl+Shift+F. Якщо слово знайдено, термінал не очищає прокрутку: очищайте її вручну (⌘K у Terminal.app та iTerm2) і закривайте вікно після роботи.

### Відомі обмеження

Програма **не може** захистити від:

- **Терміналу, що веде журнал або зберігає стан.** Журнали сесії, «відновлення вмісту вікон» у macOS і запис екрана отримують текст раніше, ніж програма встигає його стерти.
- **Програм, що читають екран або термінал.** Це AI-агенти, інструменти доступності, демонстрація екрана, віддалений доступ.
- **Копій поза програмою.** Внутрішні буфери введення .NET і пам'ять самого емулятора терміналу можуть ненадовго містити натиснуті клавіші.
- **Буфера обміну.** Будь-що скопійоване зберігається в історії менеджерів буфера обміну.
- **Шкідливого ПЗ або доступу адміністратора** до запущеного процесу.
- **Слабкого пароля.** Зашифрований текст і QR-код можна атакувати перебором паролів офлайн. PBKDF2 з 600 000 ітерацій уповільнює перебір, але не захищає від простих паролів.
- **Підробки даних.** Шифрування AES-CBC не перевіряє цілісність: пошкоджений чи змінений QR-код зазвичай дає помилку «невірний пароль», але гарантії автентичності немає.
- **Контрольної суми BIP-39.** Програма перевіряє лише те, що всі слова є в словнику BIP-39; контрольна сума фрази не перевіряється. Звіряйте розшифровану фразу з гаманцем.

### Після роботи

1. Переконайтеся, що екран очищено (прокрутіть угору).
2. Закрийте вікно або вкладку терміналу.
3. Якщо щось копіювали, очистіть історію буфера обміну.
4. Збережіть QR-код в надійному місці, а пароль окремо від нього.

## Використання

Після запуску програма пропонує вибрати режим:

1. **Згенерувати QR-код (шифрування)**
   1. Введіть сід-фразу (12 або 24 слова BIP-39 у нижньому регістрі, розділені одним пробілом, без пробілів на початку чи в кінці). Ввід маскується `*`.
   2. Введіть пароль. Ввід маскується `*`. Вимоги: мінімум 12 символів, велика й мала латинська літера (A-Z, a-z), цифра (0-9), спеціальний символ. **Запам'ятайте його: без пароля відновлення неможливе.**
   3. Вкажіть назву файлу (Enter для `seed_qr.png`; `.png` додається автоматично).
   4. Програма запитає, чи показати зашифрований текст. За замовчуванням він не показується. Якщо погодитися, текст лишається на екрані до натискання клавіші, після чого екран очищається.
2. **Розшифрувати QR-код:** шлях до файлу, потім пароль.
3. **Розшифрувати текст:** вставте зашифрований текст, потім пароль.
4. **Вийти.**

Після розшифрування програма повідомляє про успіх, але **не показує** сід-фразу, доки ви не підтвердите `y`. Показана фраза лишається на екрані до натискання клавіші, потім екран і прокрутка очищаються. Невірний пароль можна ввести повторно.

## Шифрування

- AES-256-CBC з PKCS7
- PBKDF2-HMAC-SHA256, 600 000 ітерацій, для отримання ключа з пароля
- Випадкова сіль (32 байти) і вектор ініціалізації (16 байтів) для кожного шифрування
- Формат версії 1: `версія (1 байт) | сіль (32) | IV (16) | шифротекст`, у Base64. QR-коди, створені попередніми версіями, розшифровуються без змін.
- Розшифрування відхиляє завеликі дані та некоректний UTF-8 з помилкою «невірний пароль» замість обрізаного результату.

## Можливі помилки

### Генератор
- ❌ Помилка валідації сід-фрази: неправильна кількість слів (має бути 12 або 24), слова відсутні в словнику BIP-39, пробіли на початку/в кінці або подвійні пробіли
- ❌ Помилка валідації пароля: пароль закороткий або відсутні необхідні символи
- ❌ Помилка вводу/виводу або доступу: перевірте права на запис у директорії

### Декодер
- ❌ Файл не знайдено: перевірте шлях до файлу
- ❌ Не вдалося прочитати QR-код
- ❌ Невірний пароль: невірний пароль або пошкоджені дані

### Запуск
- ❌ «ввід перенаправлено» (код 2): запустіть програму в інтерактивному терміналі без `|` та `<`
- ❌ «вивід перенаправлено»: секрет не показано, бо вивід іде у файл чи конвеєр

## Тести

### Модульні тести
```bash
dotnet test tests/QrCodeGenerator.Tests
```
Шифрування й розшифрування (зокрема тестових прикладів нижче), валідація, обнулення буферів.

### End-to-end тести консолі
Запускають зібрану програму в справжньому терміналі, вводять дані й перевіряють екран та історію прокрутки. Перевіряється: маскований ввід (зокрема посимвольний і наперед), показ і очищення сід-фрази та зашифрованого тексту, очищення при виході, Ctrl+C і помилці, відмова при перенаправленому вводі/виводі.

```bash
# tmux (без вікон; потрібен tmux: brew install tmux)
dotnet test tests/QrCodeGenerator.E2ETests

# + Terminal.app та iTerm2 (лише macOS)
QRGEN_E2E_GUI=1 dotnet test tests/QrCodeGenerator.E2ETests
```

- Без `QRGEN_E2E_GUI=1` сценарії Terminal.app та iTerm2 позначаються як пропущені (skipped) з причиною. iTerm2 також пропускається, якщо його не встановлено (`brew install --cask iterm2`).
- Перед першим запуском з GUI відкрийте iTerm2 вручну й закрийте вітальні діалоги, інакше AppleScript-виклики зависають.
- macOS попросить дозвіл на керування Terminal та iTerm2: System Settings → Privacy & Security → Automation → ваш термінал/IDE → увімкніть Terminal та iTerm2. Без дозволу тести падають з відповідним повідомленням через 20 с.
- Під час GUI-тестів відкриваються й закриваються вікна терміналів, які можуть перехоплювати фокус; не друкуйте в цей час.
- Тривалість: tmux ≈ 15 с, усі три термінали ≈ 1,5–2 хв. Тести виконуються послідовно.
- Сценарій «неочікувана помилка» використовує тестовий перемикач `QRGEN_E2E_FAULT=after-seed`, який існує лише в Debug-збірках.
